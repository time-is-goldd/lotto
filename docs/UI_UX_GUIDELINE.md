# UI/UX GUIDELINE — 40~70대 접근성 최우선 설계 원칙

> v2.0 개정(§13 온보딩/팝업 정책 추가). [[MASTER_PRD]] 타겟 사용자 정의에 따라, 이 문서의 기준은 "협상 불가" 원칙이다. 모든 화면 설계는 본 가이드라인 위반 여부를 체크한 뒤 승인한다.

---

## 1. 핵심 설계 철학

**"화면을 보자마자, 설명 없이, 3초 안에 무엇을 눌러야 할지 알아야 한다."**

20~30대 개발자/디자이너 관점의 "세련되고 조밀한 UI"는 본 서비스의 핵심 타겟에게는 오히려 장벽이다. 미니멀리즘보다 "명확함"을 우선한다.

## 2. 타이포그래피 원칙

| 요소 | 기준 |
|---|---|
| 본문 최소 크기 | 16px (모바일 기준), 절대 14px 미만 사용 금지 |
| 핵심 CTA 텍스트 | 20px 이상, Bold |
| 제목(H1) | 24~28px |
| 행간(line-height) | 1.6배 이상 (한글 가독성 확보) |
| 폰트 | 시스템 기본 산세리프(가독성 검증된 서체), 장식적 폰트 금지 |
| 숫자(번호 볼) | 별도로 시각적 강조, 최소 20px, 원형 배경 대비 확보 |

## 3. 버튼/터치 타겟 원칙

- 최소 터치 영역 44×44px (Apple/Google 접근성 가이드 기준 준수)
- 핵심 CTA 버튼은 화면 폭 대비 80% 이상, 높이 56px 이상
- 버튼 간 간격 최소 12px (오터치 방지 — 시니어 사용자 손떨림/정밀도 고려)
- 버튼 라벨은 동사형 명확 지시어 사용: "번호 생성하기" (O), "GO" "확인" 같은 모호한 라벨 지양

## 4. 색상 및 대비

- 화이트 기반 밝은 배경 원칙 (다크모드는 초기 버전에서 제공하지 않음 — 타겟 사용자군에게 다크모드는 오히려 "고장난 화면"으로 오인될 위험)
- 텍스트-배경 대비율 WCAG AA 기준(4.5:1) 이상 필수
- 색상만으로 정보를 구분하지 않음 (예: 당첨/미당첨을 색상 + 아이콘 + 텍스트 3중으로 표시)
- 상세 팔레트는 [[DESIGN_SYSTEM]] 참조

## 5. 레이아웃 및 정보 밀도

- 한 화면에 하나의 핵심 행동만 (Single Focus Principle)
- 스크롤 최소화: 핵심 기능은 접속 즉시(Above the Fold) 노출
- 복잡한 표/그래프는 시니어 대상 화면에서 요약 카드 형태로 우선 제공하고, "자세히 보기"로 상세 데이터 분리
- 팝업/모달 최소화, 사용할 경우 닫기 버튼은 항상 크고 명확한 위치(우상단 X, 최소 44px)

## 6. 아이콘 사용 원칙

- 아이콘 단독 사용 금지, 반드시 텍스트 라벨 동반 (하단 탭바 포함)
- 직관적이지 않은 추상 아이콘(예: 햄버거 메뉴만으로 "더보기" 표현) 지양 — "더보기"처럼 텍스트로 명시
- 아이콘 스타일은 통일된 라인/필 스타일 하나로 고정 ([[DESIGN_SYSTEM]] 아이콘 세트 참조)

## 7. 입력 폼 원칙 (운세 입력, 회원가입 등)

- 입력 필드 최소화 — 운세 기능은 생년월일/성별만 필수, 나머지 선택
- 날짜 입력은 텍스트 타이핑이 아닌 드럼롤/드롭다운 선택 방식 우선 (시니어 오타 방지)
- 에러 메시지는 빨간 텍스트 단독이 아닌, 아이콘+구체적 안내文("생년월일을 다시 확인해주세요, 예: 1965년 3월 5일")
- 필수 입력값은 별표(*) 외에 "필수" 텍스트 병기

## 8. 피드백 및 상태 표시

- 로딩 상태는 반드시 시각적 표시(스피너/프로그레스) + "번호를 생성하고 있어요..." 텍스트 동반 (빈 화면 금지)
- 저장/완료 액션은 토스트 메시지로 명확히 확인 ("저장되었습니다" 최소 2초 이상 노출)
- 네트워크 오류 시 기술 용어(예: "500 Error") 노출 금지, "일시적으로 연결이 어려워요, 다시 시도해주세요" 등 일상어 사용

## 9. 내비게이션 원칙

- 뒤로가기는 항상 예측 가능하게 동작 (브라우저 뒤로가기와 화면 내 뒤로가기 버튼 동작 일치)
- 현재 위치를 항상 표시 (하단 탭 활성 상태 강조, 브레드크럼)
- 딥링크(카카오 공유 등으로 진입) 시에도 상단에 "홈으로" 이동 경로 항상 노출

## 10. 콘텐츠 톤앤매너

- 존댓말 기본, 친근하되 과도한 은어/인터넷 밈 지양(전 연령 이해 가능한 표현)
- 숫자/데이터는 항상 단위와 함께 표기("1,150회" O, "1150" 단독 지양)
- 사행성 자극 문구 배제, 재미와 신뢰를 동시에 주는 톤 유지 ([[MASTER_PRD]] 비목표 원칙과 연동)

## 11. 접근성(Accessibility) 체크리스트

- [ ] 모든 이미지에 대체 텍스트(alt) 제공
- [ ] 키보드만으로 핵심 흐름(번호생성→다이어리 기록) 조작 가능
- [ ] 스크린리더 호환 (시맨틱 HTML, ARIA 라벨)
- [ ] 폰트 크기 브라우저/OS 확대(최대 200%) 시에도 레이아웃 깨짐 없음
- [ ] 애니메이션은 3초 이내로 제한하고 "애니메이션 줄이기" 시스템 설정 존중(prefers-reduced-motion)

## 12. 검수 프로세스

모든 신규 화면은 출시 전 아래 시나리오로 자체 점검한다:
1. 60대 이상 실제 사용자 3인 이상 사용성 테스트 (가능 시)
2. 화면을 처음 보는 사람에게 "무엇을 눌러야 할 것 같은가" 질문 → 3초 내 정답률 측정
3. 글자 크기 150% 확대 상태에서 레이아웃 깨짐 여부 확인

## 13. 온보딩 및 팝업 정책 (신규, [[CRITICAL_REVIEW]] P-07/U-04 반영)

### 13.1 최초 방문 온보딩
첫 방문자에게 3장 이내의 간단한 소개 슬라이드(스킵 가능)를 1회 노출한다: ①"번호를 뽑아보세요" ②"모든 기록이 다이어리에 쌓여요" ③"당첨되면 알려드려요". 텍스트는 §10 톤앤매너를 따르고, 슬라이드당 최대 2문장으로 제한한다. 재방문 시에는 노출하지 않는다.

### 13.2 팝업/모달 금지 원칙 (강화)
**Exit-intent(이탈 감지) 팝업은 사용하지 않는다.** 모바일에서는 트리거가 불안정하고, 시니어 사용자에게는 "갑자기 튀어나오는 화면"으로 인식되어 오히려 이탈을 유발한다. 회원가입 유도 등은 대신 화면 하단에 항상 붙어있는 얇은 고정 배너(닫기 가능, 재노출 안 함)로 대체한다. 팝업은 사용자가 명시적으로 행동을 완료했을 때(예: 당첨 축하)만 사용한다.

### 13.3 다이어리 탭 우선 원칙
[[INFORMATION_ARCHITECTURE]] 개정에 따라 하단 탭바의 4번째 자리는 "다이어리"가 고정 차지한다. 새로운 기능이 추가되더라도 다이어리를 하단 탭에서 밀어내지 않는다 — 다이어리는 플랫폼의 정체성이므로 항상 3초 안에 도달 가능해야 한다 ([[MASTER_PRD]] §0).
