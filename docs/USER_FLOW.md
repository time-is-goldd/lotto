# USER FLOW — 전체 사용자 흐름 설계 (Luck Platform / 다이어리 중심 개정판)

> v2.0. [[MASTER_PRD]] §0의 재정의("핵심은 번호생성이 아니라 행운 다이어리")를 반영해 전체 퍼널의 중심을 다이어리로 이동했다. URL은 [[SITEMAP]] v2.0 기준(`/my/journal/*`)을 따른다.

---

## 1. 전체 퍼널 개요 (개정)

```
[유입] → [번호생성 체험] → [다이어리에 자동 기록] → [재방문]
   → [꿈기록/AI운세로 다이어리 확장] → [통계/공유] → [(장기) 쇼핑몰/멤버십]
```

v1.0과의 차이: v1.0은 "번호생성 → 탐색 → 가입 → 저장 → 당첨확인 → 공유 → 커뮤니티 → 구매"였다. v2.0은 저장·당첨확인이 모두 **다이어리라는 하나의 목적지로 수렴**한다는 것을 명시적으로 표현한다. 사용자는 "번호를 저장한다"고 인지하는 게 아니라 "다이어리에 기록된다"고 인지해야 한다.

---

## 2. 진입 경로(Entry Point)별 흐름

### 2.1 검색 유입 — "로또 번호 생성"
```
검색 → /generate 랜딩 → 1클릭 번호 6개 출력(비로그인 가능)
 → 결과 화면: "이 번호, 다이어리에 기록해두고 당첨되면 알림 받기" CTA
```
v1.0 대비 CTA 문구를 "저장"에서 "다이어리에 기록"으로 변경 — 처음 접하는 순간부터 다이어리 개념을 각인시킨다.

### 2.2 검색 유입 — "꿈해몽"
```
검색(예: "돼지꿈 로또번호") → /dream/[keyword] → "행운번호 보기" → /dream/[keyword]/numbers
 → "실제 당첨 사례" 카드 → "나도 이 방식으로 생성하기" → /generate?source=dream
```
기존과 동일 (변경 없음).

### 2.3 카카오톡 공유 유입 (바이럴, 확장)
```
친구 공유 링크 클릭 → /share/[shareId] 랜딩
 → "나도 내 운세 보기" 또는 "나도 다이어리 만들기" CTA
 → /fortune 또는 /invite/[inviteCode](친구초대 경유 시, 신규) 로 이동
```
**신규**: 친구 초대 링크(`/invite/[inviteCode]`)를 통한 진입 시, 친구가 초대했음을 명시("OOO님이 초대했어요")하고 가입 완료 시 양쪽에 비현금 보상을 안내 ([[FEATURE_SPEC]] §8).

### 2.4 재방문 — 알림 클릭 (개정)
```
당첨 알림 수신 → /my/journal/results 직행 (구 "/my/results")
 → 당첨 시: 축하 연출 + "다이어리에 기록되었어요" + 공유 CTA
 → 미당첨 시: "이번주 운세도 확인해보세요" 또는 "꿈 기록 남기기" CTA (다이어리 내 다른 활동 유도)
```

## 3. 핵심 루프 상세 (개정 — 다이어리 중심 9단계)

MVP([[ROADMAP]] MoSCoW)에서 실제 구현되는 것은 STEP 1~4이며, STEP 5~9는 Phase별로 순차 도입된다.

### STEP 1. 번호 생성 (Must)
`/generate` — 완전자동 생성(MVP) → 결과 노출 → 로그인 시 자동으로 다이어리에 기록, 비로그인 시 "로그인하면 다이어리에 기록돼요" 배너.

### STEP 2. 다이어리 기록 (Must, 구 "번호저장")
로그인 상태에서 번호 생성 시 별도 클릭 없이 `/my/journal/history`에 자동 반영. 저장이라는 단어 대신 "다이어리에 기록되었어요" 토스트 사용.

### STEP 3. 당첨 확인 (Must)
회차 결과가 등록되면 배치가 자동 대조 → `/my/journal/results`에 반영 → 알림 발송(사이트내/이메일/웹푸시).

### STEP 4. 꿈 기록 / AI 운세 (Should)
`/my/journal/dreams`(개인 꿈 일기), `/fortune`(AI 운세) 이용 시 결과가 자동으로 `/my/journal/fortune-history`에 누적. "오늘 꾼 꿈을 기록해보세요" 같은 넛지를 다이어리 화면에 배치해 순수 기록형 참여(번호 생성 없이도 다이어리를 채우는 행동)를 유도한다.

### STEP 5. 통계 확인 (Could)
`/my/journal/stats`에서 월간/연간 통계 열람. 사이트 전체 통계(`/statistics`)와 개인 통계를 서로 링크.

### STEP 6. 공유 (Must~Should)
번호/운세/당첨결과/연말리포트를 카카오로 공유. 공유 클릭 시 §2.3 흐름으로 순환(바이럴 루프).

### STEP 7. 친구 초대/배틀 (Should, Phase 4)
```
/invite 진입 → 초대링크 생성/공유 → 친구 가입 완료 시 양쪽 비현금 보상
 → "친구와 배틀" 진입 → 친구 랭킹에서 서로 비교
```

### STEP 8. 커뮤니티 참여 (Phase 4, MVP 범위 아님)
`/community` 게시판, 배틀 인증 등 — v1.0 STEP8과 동일하되 시점만 Phase 4로 이동.

### STEP 9. 쇼핑몰/멤버십 (Phase 5~7, 장기)
연말 Luck Report 고급판, 프리미엄 멤버십 가입 유도 — `/my/journal/yearly-report`에서 자연 연결.

## 4. 이탈 방지 지점 (개정)

| 이탈 위험 지점 | 원인 | 대응 (v2.0) |
|---|---|---|
| 번호 생성 직후 | 목적 달성 이탈 | "다이어리에 기록해두면 당첨 시 알려드려요" 가치 제시 (v1.0의 "관련콘텐츠 3종 추천"보다 다이어리 가치 강조로 단순화 — 홈 스크롤 최소화 원칙과 정합, [[INFORMATION_ARCHITECTURE]]) |
| 로그인 요구 시점 | 가입 마찰 | 카카오 1클릭, "다이어리를 만들려면 로그인이 필요해요"로 이유를 명확히 설명 |
| 다이어리 첫 진입(빈 상태) | 콘텐츠 없어 허전함 | 빈 상태에서도 "첫 기록을 남겨보세요" CTA(번호생성/꿈기록/운세 중 택1 유도) |
| 당첨 결과 미당첨 시 | 실망 이탈 | 배틀/커뮤니티 대신(Phase4 이전에는 존재하지 않으므로) "꿈 기록"이나 "다음 회차 운세 확인"으로 유도 |
| 친구초대 링크 클릭 후 미가입 | 가치 불명확 | 랜딩에서 다이어리 미리보기(예시 화면)를 먼저 보여준 뒤 가입 유도 |

## 5. 크로스 디바이스 흐름 — 유지

모바일 우선, 카카오톡 인앱 브라우저 대응 필수, 시니어 글자 확대 대응 ([[UI_UX_GUIDELINE]]) 원칙은 그대로 유지한다.
