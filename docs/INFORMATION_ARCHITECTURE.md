# INFORMATION ARCHITECTURE — 정보 구조 및 내비게이션 설계 (Luck Platform 개정판)

> v2.0. [[SITEMAP]] v2.0의 Luck Platform 구조를 실제 메뉴/내비게이션으로 변환한다. [[CRITICAL_REVIEW]] U-01(당첨사례/당첨확인 혼동), U-02(홈 스크롤 과다), U-03(배틀/게시판 도달성)을 해결하는 것이 이번 개정의 핵심 목표다.

---

## 1. 내비게이션 체계 개요 (개정)

### 1.1 데스크톱 GNB
```
[로고]   번호생성   꿈해몽   운세   다이어리   더보기   [로그인/프로필]
```
- v1.0에서는 "통계/배틀/당첨사례/커뮤니티"가 개별 메뉴였으나, MVP 범위 축소([[ROADMAP]] MoSCoW)에 맞춰 초기 GNB는 5개로 단순화한다. 배틀·커뮤니티·명예의전당·통계·당첨사례는 Phase 4 이후 순차 노출.
- **"다이어리"를 GNB에 정식 메뉴로 승격** — 이는 v1.0에서 "당첨확인"이 하단탭에만 있던 것과 달리, Lucky Journal이 플랫폼의 정체성이므로 데스크톱에서도 항상 보이는 위치에 둔다.

### 1.2 모바일 하단 탭바 (개정 — 핵심 변경)
```
[홈]   [번호생성]   [운세]   [다이어리]   [더보기]
```
- **"당첨확인" 탭을 "다이어리" 탭으로 교체.** 당첨확인은 다이어리의 하위 기능(`/my/journal/results`)으로 흡수되어 별도 탭이 필요 없어졌고, 동시에 [[CRITICAL_REVIEW]] U-01의 "당첨사례 vs 당첨확인" 명칭 충돌이 구조적으로 해소된다. `/winners`(당첨사례)는 "더보기"에서만 접근 가능한 공개 콘텐츠로 명확히 분리된다.
- 비로그인 상태에서 "다이어리" 탭 클릭 시 빈 화면 대신 "로그인하면 번호·운세·꿈 기록이 모두 여기 쌓여요" 안내 화면 + 로그인 CTA 노출 (단순 리다이렉트보다 가치 설명 우선).

### 1.3 "더보기" 그리드 메뉴 구조 (개정)
```
┌─────────┬─────────┬─────────┐
│  통계   │  배틀   │명예의전당│   (Phase 4 이후 노출)
├─────────┼─────────┼─────────┤
│ 당첨사례 │ 커뮤니티 │  로또명당│
├─────────┼─────────┼─────────┤
│  친구초대 │ 가이드  │  FAQ   │
└─────────┴─────────┴─────────┘
```
MVP 단계에서는 배틀/명예의전당/커뮤니티 칸은 "Coming Soon" 상태로 비활성 표시하거나 아예 숨기고, 당첨사례/로또명당/가이드/FAQ만 노출한다 ([[ROADMAP]] Phase 1 범위 준수).

## 2. 홈페이지(`/`) 정보 구조 — 개정 (스크롤 최소화)

[[CRITICAL_REVIEW]] U-02 지적("Hero→카드→배틀배너→실시간로그→당첨하이라이트→명예의전당→콘텐츠추천→Footer" 8섹션은 과다)을 반영해 로그인 상태별로 분기한다.

### 2.1 비회원 홈 (최대 4섹션)
```
[Hero] 카피 + "번호 생성하기" CTA + 오늘 생성 건수
   ↓
[빠른 실행 카드 3종] 번호생성 / 꿈해몽 / 운세
   ↓
[다이어리 가치 설명 배너] "당신의 행운을 기록해보세요" + 회원가입 CTA
   ↓
[Footer]
```

### 2.2 회원 홈 (최대 5섹션)
```
[내 다이어리 요약 카드] "이번달 N번 생성, 최고기록 M개 일치" — 최상단 고정
   ↓
[Hero/빠른실행] 번호생성 / 꿈해몽 / 운세
   ↓
[이번주 당첨사례 하이라이트] (Phase 2 이후)
   ↓
[Footer]
```
실시간 생성 로그, 명예의 전당 미리보기, 콘텐츠 추천 섹션은 v1.0에서 홈 하단에 있었으나, 가치 대비 스크롤 비용이 크다고 판단해 **홈에서 제외하고 각 기능의 개별 페이지 내부로 이동**한다 (예: 실시간 로그는 `/generate` 결과 화면 내에만 노출).

## 3. 카테고리 체계 (Taxonomy) — 유지 + 확장

### 3.1 꿈해몽 카테고리 — 유지
동물/자연/사람/사물·금전/행동·상황 (기존과 동일)

### 3.2 커뮤니티 카테고리 — 유지 (Phase 4 적용)
자유수다/당첨인증/번호나눔/꿈해몽나눔/배틀인증 (기존과 동일)

### 3.3 신규: 로또 명당(Store) 카테고리
```
로또명당
├── 지역별 (시/도 → 구/군)
└── 1등 배출 횟수 랭킹
```

### 3.4 신규: 행운 다이어리 내부 탭 구조
```
행운 다이어리
├── 히스토리 (생성/저장 전체 목록)
├── 당첨확인 (구 "당첨확인" 기능 흡수)
├── 캘린더
├── 꿈 기록
├── 운세 기록
├── 통계 (월간/연간)
└── 연말 리포트
```

## 4. 검색 기능 — 유지

헤더 상단 고정 검색 아이콘, 꿈해몽 키워드 자동완성. 검색 결과 통합 노출(꿈해몽/커뮤니티/FAQ/로또명당 탭 추가).

## 5. 브레드크럼 구조 — 확장

```
홈 > 꿈해몽 > 동물 > 돼지꿈
홈 > 로또명당 > 서울 > 강남구 > OO복권방
홈 > 다이어리 > 캘린더  (다이어리 내부는 noindex이므로 SEO 목적 아님, UX 목적으로만 적용)
```

## 6. 정보 우선순위 원칙 (3초 법칙) — 유지, 재검증

[[CRITICAL_REVIEW]] U-03에서 지적된 "배틀/게시판이 더보기 2탭 뒤에 있다"는 문제는, MVP 단계에서는 배틀/게시판 자체가 Won't(제외 대상)이므로 **당장은 문제가 되지 않는다.** Phase 4에서 배틀/커뮤니티가 재도입될 때, 홈 화면에 배틀 배너를 다시 노출할지, GNB에 재편입할지는 그 시점 사용자 데이터(어떤 기능이 실제로 많이 쓰이는지)를 보고 결정한다 — 지금 미리 자리를 예약해두지 않는다 (§[[MASTER_PRD]] 원칙 5: 확장성보다 현실성).

## 7. 회원/비회원 정보 구조 차이 — 개정

| 영역 | 비회원 | 회원 |
|---|---|---|
| GNB/탭 "다이어리" | 가치 설명 + 로그인 유도 화면 | 실제 기록 데이터 |
| 번호생성 결과 | 저장 불가, 로그인 유도 배너(닫기 가능) | 자동 저장 + "다이어리에 저장됨" 토스트 |
| 커뮤니티(Phase 4) | 열람만 | 작성/댓글/추천 |

## 8. 온보딩 (신규 — [[CRITICAL_REVIEW]] P-07 반영)

첫 방문자에게 3장 이내의 간단한 소개 슬라이드(스킵 가능)를 최초 1회 노출한다: ①"번호를 뽑아보세요" ②"모든 기록이 다이어리에 쌓여요" ③"당첨되면 알려드려요". 시니어 사용자의 첫 진입 혼란을 줄이기 위한 최소 장치이며, 개발 비용이 낮아 MVP(Should)에 포함 가능하다.
