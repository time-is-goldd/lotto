# SEO STRATEGY — 검색 유입 전략 (Luck Platform 개정판)

> v2.0. [[CRITICAL_REVIEW]] S-01~S-06(로또명당 누락, 백링크 전략 부재, 툴 콘텐츠 부재 등)을 반영하고, [[MASTER_PRD]] §0 Luck Platform 확장(로또 외 운세/꿈/통계 브랜치)에 맞춰 키워드 전략을 전면 확장한다.

## 1. 키워드 전략 (확장)

### 1.1 키워드 클러스터 분류 (개정 — 신규 클러스터 추가)

| 클러스터 | 예시 키워드 | 검색 의도 | 대응 페이지 | 상태 |
|---|---|---|---|---|
| 핵심 기능형 | 로또번호생성, 로또 번호 추천, 자동번호 | 즉시 행동 | `/generate` | 기존 |
| 꿈해몽 롱테일 | 돼지꿈 로또번호, 뱀꿈 해몽, 물꿈 로또 | 정보+행동 | `/dream/[keyword]` | 기존 |
| 운세형 (확장) | 오늘의 운세, 신년운세, 띠별 운세, 별자리 운세, 사주팔자, 토정비결 | 정보+개인화 | `/fortune`, 향후 운세 콘텐츠 허브 | **신규 확장** |
| 회차/결과형 | 1150회 로또 당첨번호, 이번주 로또 결과, 로또 QR 확인 | 정보 확인 | `/winners/round/[round]` | 기존+확장 |
| **로또 명당 (신규)** | 로또 명당, 로또 1등 판매점, 우리동네 로또명당, [지역명] 로또 판매점 | 정보+행동(방문) | `/store/*` | **신규, 최대 기회** |
| **계산기/툴형 (신규)** | 로또 세금 계산기, 당첨금 실수령액 | 정보+도구 사용 | `/tools/tax-calculator` | **신규** |

| 신뢰/가이드형 | 로또 당첨금 수령방법, 로또 세금 | 정보+신뢰 | `/guide/*`, `/faq/*` | 기존 |
| 커뮤니티형 | 로또 당첨 후기, 로또 당첨 인증 | 사회적 증거 탐색 | `/community/*` (Phase 4) | 기존 |

### 1.2 신규 발굴 키워드 (누락되어 있던 고검색량 영역)

[[CRITICAL_REVIEW]]가 지적한 "로또 명당" 외에, Luck Platform 확장 관점에서 아래 키워드군이 추가로 누락되어 있었다.

1. **로또 명당/판매점** — "로또 명당", "1등 판매점", "[지역명] 로또 잘되는 곳" 등. 한국 로또 검색에서 최상위권 볼륨. 압도적 최우선 신규 기회.
2. **운세 콘텐츠 다각화** — "오늘의 운세", "신년운세", "띠별 운세", "별자리 운세". 기존 설계는 "생년월일 기반 AI 운세" 단일 기능에 그쳤으나, 이 키워드들은 각각 독립적인 검색 볼륨을 가진 콘텐츠 카테고리다. Fortune 브랜치 하위에 콘텐츠 페이지로 확장 가능.
3. **계산기형 툴** — "로또 세금 계산기", "당첨금 실수령액". 개발 난이도 낮고 백링크 유도력이 큰 콘텐츠.
4. **로또 QR 확인** — 실물 용지 QR 스캔 관련 정보성 검색. 가이드 콘텐츠로 흡수 가능(`/guide/qr확인방법`).
5. **연금복권 등 인접 상품 정보성 키워드** — 직접 서비스 대상은 아니지만 "복권" 검색 사용자와 겹치는 트래픽 풀. 가이드/FAQ에서 비교 정보로 가볍게 다뤄 유입 저변 확대 가능(Could, 후순위).
6. **궁합형 키워드** — "이름궁합", "사주궁합" 등은 §8 Growth의 "번호 궁합 테스트" 기능과 직결되는 키워드군. 기능이 만들어지면 자동으로 이 클러스터를 흡수한다.

### 1.3 원칙 (유지)
- Head 키워드는 UX 완성도(체류시간, 재방문율)로 승부.
- **로또 명당 클러스터가 이제 꿈해몽과 함께 최대 기회 영역**으로 격상됨 — 콘텐츠 허브 우선순위 1위.
- 회차형 키워드는 매주 자동 생성되는 자산이라는 점 유지.

## 2. 콘텐츠 허브 전략 (개정 — 허브 3개로 확장)

```
[허브1: /dream] 꿈해몽 — 기존 구조 유지 (카테고리 5종 → 개별 키워드)

[허브2: /store] 로또 명당 (신규)
     │
     ├── [클러스터: /store/region/서울] → 개별 [/store/123], [/store/456] ...
     ├── [클러스터: /store/region/경기]
     └── ... (전국 시/도별)

[허브3: /winners] 당첨사례 — 기존 구조 유지 (회차별 자동 누적)

[허브4: /statistics] 통계 — 기존 구조 유지

[보조 콘텐츠: /tools] 계산기형 — 허브라기보다 개별 고전환 랜딩 페이지 성격
[보조 콘텐츠: /fortune 콘텐츠 확장] 오늘의 운세/신년운세 등 — Phase 2 이후 별도 허브 승격 검토
```

로또 명당 허브는 데이터만 확보되면(§공공데이터 활용) 자동 생성 가능한 페이지 수가 매우 많아(전국 판매점 수천 곳), 사이트 전체 색인 페이지 수를 크게 늘리는 효과가 있다 — 이는 도메인 전체의 검색엔진 권위(Topical Authority)에도 기여한다.

## 3. 카테고리 전략 — 유지 + 로또명당 추가

`/store/region/[region]` 카테고리 목록 페이지에도 고유 소개 텍스트(200자 이상)를 배치해 얇은 콘텐츠 판정을 피한다 (기존 원칙과 동일 적용).

## 4. 구조화 데이터 (Schema/JSON-LD) — 확장

기존 표(FAQPage, HowTo, Article, BreadcrumbList, WebSite, DiscussionForumPosting, Product)에 추가:

| 페이지 | 적용 Schema | 목적 |
|---|---|---|
| `/store/[storeId]` | `LocalBusiness` | 판매점 지역 검색 리치결과 (신규) |
| `/tools/tax-calculator` | `WebApplication` 또는 `HowTo` | 계산기 도구 리치결과 (신규) |

## 5. Breadcrumb 전략 — 확장

```
홈 > 로또명당 > 서울 > 강남구 > OO복권방
```
기존 원칙과 동일하게 적용.

## 6. 내부 링크 전략 — 확장

기존 4개 원칙(꿈해몽 상호링크, 기능간 교차링크, 회차 시계열 링크, 앵커텍스트 다양화)에 추가:

5. **로또명당 ↔ 당첨사례 교차 링크**: 특정 판매점에서 나온 1등 사례가 있으면 `/winners/round/[round]`와 `/store/[storeId]`를 상호 링크 — 두 콘텐츠 축이 서로의 SEO 가치를 강화.
6. **운세 콘텐츠 ↔ 번호생성 순환**: "오늘의 운세" 등 확장 콘텐츠에서도 기존 원칙대로 번호생성으로 연결되는 CTA 배치.

## 7. Canonical 전략 — 유지

`/my/journal/*`(구 `/my/*`) 전체 `noindex, nofollow` 유지. `/invite/[inviteCode]`도 개인화 추적 URL이므로 `noindex` 추가.

## 8. XML Sitemap — 확장

기존 5종에 `sitemap-store.xml`(신규, 판매점), `sitemap-tools.xml`(신규, 계산기) 추가. [[SITEMAP]] §5 참조.

## 12. 백링크(Off-page SEO) 전략 (신규, [[CRITICAL_REVIEW]] S-03 해결)

v1.0에서 전혀 다루지 않았던 영역. 1인 운영 기준으로 실행 가능한 저비용 백링크 확보 방법을 명시한다.

1. **계산기/툴 콘텐츠(§1.2 §3)를 백링크 미끼로 활용**: 세금 계산기 등은 커뮤니티/블로그에서 자연 링크되기 쉬운 콘텐츠 유형.
2. **로또 명당 데이터의 지역 커뮤니티 자연 링크**: 지역 맘카페, 지역 커뮤니티에서 "우리 동네 로또명당" 콘텐츠는 자연스럽게 공유·링크되는 경향.
3. **연말 Luck Report(§[[FEATURE_SPEC]] §0.5) 공유 유도**: 개인화 리포트가 소셜에 공유되면서 발생하는 자연 링크.
4. **적극적 아웃리치는 1인 운영 리소스 안에서 후순위**: 보도자료 배포, 제휴 콘텐츠 등은 Phase 4 이후 유료 마케팅 예산이 생겼을 때 검토 (지금은 콘텐츠 자체의 자연 링크 유도에 집중).

## 13. AI 검색(Google AI Overview 등) 대응 (신규, [[CRITICAL_REVIEW]] S-05)

- FAQ/가이드 콘텐츠를 "질문-짧은 명확한 답변" 구조로 작성해 AI 답변 엔진의 인용 가능성을 높인다 ([[CONTENT_STRATEGY]] 작성 가이드 반영).
- 향후 `llms.txt` 등 AI 크롤러 대상 메타데이터 표준이 정착되면 도입 검토 (현재는 표준 미확정, Could/모니터링 대상).

## 14. 측정 및 모니터링 — 유지

Google Search Console + 네이버 서치어드바이저 동시 등록. 클러스터별(§1.1) 노출/클릭을 분리 트래킹하되, **신규 클러스터(로또명당, 운세확장, 계산기)의 초기 성과를 별도로 추적**해 [[CONTENT_STRATEGY]] 콘텐츠 투자 우선순위에 반영한다.
