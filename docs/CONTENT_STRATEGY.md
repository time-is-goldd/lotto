# CONTENT STRATEGY — 콘텐츠 운영 전략 (1인 운영 / 자동화 우선 개정판)

> v2.0. [[SEO_STRATEGY]] v2.0(로또명당/계산기 등 신규 클러스터)과 [[ROADMAP]] v2.0(Phase 0~8, 1인 개발 기준)에 맞춰 전면 개정한다. [[MASTER_PRD]] §3 원칙(운영 자동화 최우선, AI 위임 우선)에 따라 "운영팀 작성"을 전제한 v1.0의 생산 계획을 1인 운영 + AI 초안 워크플로 기준으로 재조정했다.

---

## 1. 콘텐츠 유형 분류 (개정)

| 유형 | 생산 주체 (개정) | 갱신 빈도 | 목적 |
|---|---|---|---|
| 꿈해몽 사전 | **1인 운영자 작성(MVP 최소 20~30건)** → Phase 8: AI 초안+운영자 승인 | MVP 이후 월 10~20건 추가 | 롱테일 SEO |
| 회차별 당첨사례 | 운영자 큐레이션(최소) → Phase 8: AI 초안 | 주 1회 | 신뢰도 + 최신성 |
| 로또 명당(판매점) 콘텐츠 (신규) | 공공데이터 임포트 + 운영자 검수 | 데이터 갱신 시 | SEO 최대 기회 클러스터 ([[SEO_STRATEGY]]) |
| 계산기형 콘텐츠 (신규) | 1회성 개발 후 정적 유지 | 거의 없음 | 백링크/전환용 |
| 운세 콘텐츠(템플릿) | 운영자 작성(MVP는 최소 템플릿) | 최초 구축 후 필요시 보강 | 개인화 재방문 |
| 통계 콘텐츠 | 자동 배치 생성 | 주 1회 자동 | 데이터 기반 재방문 |
| 커뮤니티 UGC | 사용자 생성 (Phase 4부터) | 실시간 | 롱테일 + 사회적 증거 |
| 가이드/FAQ | 운영자 작성(MVP 최소 3~5편) | 필요시 검토 | 신뢰도(E-E-A-T) |
| 공지/이벤트 | 운영자 | 수시 | 재방문 트리거 |

## 2. 콘텐츠 생산 로드맵 (개정 — [[ROADMAP]] Phase 0~8과 정합)

### Phase 0 (기획, 출시 전)
- 꿈해몽 사전 **최소 20~30개 키워드**(카테고리별 4~6개, [[INFORMATION_ARCHITECTURE]] §3.1 기준) — v1.0의 200개는 1인 운영에 과도했던 목표로 재조정
- FAQ 최소 5문항, 가이드 최소 3편
- 과거 회차 데이터 최근 1~2년치 `draws` 백필

### Phase 1 (MVP, 4~6주)
- 꿈해몽/가이드는 Phase 0 분량 그대로 운영, 신규 생산은 여유 될 때만(강제 목표 없음 — MVP 기간엔 기능 구축이 최우선, [[ROADMAP]] MoSCoW)
- 당첨사례는 매주 1건만 최소 등록

### Phase 2~3 (회원기능/다이어리 고도화)
- 꿈해몽 주 5~10건씩 점진 추가
- 연말 Luck Report 콘텐츠 템플릿 준비 ([[FEATURE_SPEC]] §0.5)

### Phase 4 (커뮤니티)
- 커뮤니티 초기 활성화를 위한 운영자 시드 게시글(당첨인증/배틀후기 예시) 배치
- 친구초대/배틀 관련 안내 콘텐츠

### Phase 5 이후 (쇼핑몰~AI자동화운영)
- 로또 명당 콘텐츠 본격 확장(지역별)
- **Phase 8부터 꿈해몽/당첨사례를 "AI 초안 생성 → 운영자 검토·발행" 워크플로로 전환** ([[ADMIN_REQUIREMENTS]] §10) — 이 시점부터 콘텐츠 생산 속도가 크게 빨라지므로, 그 이전까지는 무리하게 콘텐츠 양으로 승부하지 않는다.
- UGC 비중 확대, 시즌 콘텐츠 기획

## 3. 주간 발행 캘린더 (운영 루틴)

[[USER_PSYCHOLOGY]] §3 주간 리듬과 정확히 동기화한다. **아래 캘린더는 Phase 4(커뮤니티/배틀) 도입 이후를 전제로 한 풀 버전이다. MVP(Phase 1) 기간에는 "배틀" 관련 행만 제외하고, 토요일 당첨사례 등록과 통계 갱신 확인만 수행한다** — 1인 운영자가 매주 처리해야 할 작업량을 MVP 단계에서 최소화하기 위함이다.

| 요일 | 콘텐츠 작업 | 목적 |
|---|---|---|
| 월 | 지난주 통계 데이터 검증, 커뮤니티 우수글 큐레이션 | 콘텐츠 신선도 |
| 화~수 | 신규 꿈해몽 콘텐츠 5~10건 발행 | 롱테일 누적 |
| 목 | "이번주 번호 어떻게 뽑을까" 유형 콘텐츠/배너 예약 | 리마인드 심리 대응 |
| 금 | 배틀 마감 임박 알림 콘텐츠 준비 | 참여 독려 |
| 토(추첨일) | 추첨 직후 `draws` 입력 → 당첨사례 초안 작성 시작 | 최신성 확보 |
| 일 | 당첨사례 발행 완료, 통계 캐시 갱신 확인, 명예의전당 정산 | 재방문 트리거 완성 |

## 4. 콘텐츠 품질 기준

- 꿈해몽 본문: 최소 400자 이상, 유사 문구 반복(스핀 콘텐츠) 금지 — 각 키워드별 실질적으로 다른 해석/맥락 포함
- 모든 콘텐츠에 "당첨을 보장하지 않는다"는 면책 문구 하단 고지 통일 ([[MASTER_PRD]] 비목표 원칙)
- 시니어 가독성 기준 준수: 한자어/전문용어 최소화, 문장 길이 40자 이내 권장 ([[UI_UX_GUIDELINE]] 참조)

## 5. 커뮤니티 콘텐츠 활성화 전략

- **초기 콜드스타트 문제 대응**: 운영팀이 각 카테고리별 시드 게시글 10건 이상 선등록하여 "활성 커뮤니티처럼 보이게" 초기 임계질량 확보
- **참여 허들 낮추기**: 글쓰기보다 진입장벽 낮은 "리액션(추천)"과 "댓글"을 우선 유도하는 UI 배치
- **배틀-커뮤니티 연동**: 배틀 결과 발표 직후 "인증글 남기면 뱃지 지급" 등 낮은 보상으로 UGC 생산 촉진

## 6. 콘텐츠 거버넌스

- 모든 발행 콘텐츠는 관리자 CMS를 통해 `is_published` 플래그로 제어 ([[ADMIN_REQUIREMENTS]] 참조)
- 사행성/자극적 문구 필터링을 위한 발행 전 체크리스트 운영 (금지어 리스트: "확정", "보장", "무조건" 등)
- 커뮤니티 UGC는 신고 누적 시 자동 숨김 임계치 설정 (예: 신고 5건 이상 자동 `status='reported'` 전환 후 관리자 검토)

## 7. 콘텐츠 성과 측정

| 지표 | 측정 대상 | 활용 |
|---|---|---|
| 키워드별 검색 노출/클릭 | 꿈해몽, 통계, 가이드 | 신규 콘텐츠 우선순위 결정 |
| 페이지별 체류시간 | 전체 콘텐츠 | 콘텐츠 품질 개선 대상 선정 |
| 콘텐츠→기능 전환율 | 꿈해몽→번호생성, 운세→공유 | UX 흐름 개선 근거 |
| UGC 생산량/신고율 | 커뮤니티 | 운영 리소스 배분 |
