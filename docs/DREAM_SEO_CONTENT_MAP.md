# Dream SEO Content Map (Phase10-9)

Luck Platform 꿈해몽을 "25개 대표 꿈 + 101개 세부 상황"의 작은 기능에서, 한국어 꿈 검색어에
지속적으로 대응할 수 있는 콘텐츠 자산으로 확장하기 위한 keyword research 결과와 우선순위 문서다.

## 1. 조사 방법

- 웹 검색으로 실제 한국어 꿈해몽 콘텐츠 사이트(사주플러스, 별담, 홍심당, 몽담, 운명공학 등)의
  구조와 다루는 꿈 종류를 확인했다. 검색 결과 공통적으로 확인된 사실:
  - 뱀꿈·돼지꿈·이빨 빠지는 꿈·조상꿈이 한국에서 가장 널리 검색되는 "국룡" 꿈 소재로 반복 등장한다
    — 이미 Luck Platform의 기존 25개 안에 전부 포함되어 있어(뱀꿈/돼지꿈/이빨 빠지는 꿈/조상이
    나타나는 꿈), 기존 우선순위 판단이 실제 검색 시장과 일치했음을 재확인했다.
  - 상위 사이트들은 "동물/신체/인물/자연/상황/사물" 같은 카테고리 분류 + 상황별 세부 페이지
    구조를 공통적으로 쓴다 — 기존 dreams.category 체계(동물/신체/인물/상황/자연/행동/사물)와
    이미 일치한다. 새 taxonomy를 발명하지 않았다.
  - 고양이꿈 하나만 다루는 사이트가 "50가지 의미"급으로 세분화하는 사례가 확인돼, 고양이꿈이
    실제로 상황 편차가 큰 P1 후보임을 뒷받침한다.
  - 이빨 빠지는 꿈은 "윗니/아랫니", "피가 났는지", "빠진 개수" 등 신체 세부 조건에 따라 해석이
    갈린다는 것이 여러 사이트에서 공통적으로 확인됐다 — 기존 Luck Platform의 이빨 빠지는 꿈(4개)이
    이 편차를 아직 충분히 담지 못하고 있다는 근거가 된다(Gap Analysis §4).
- 경쟁 사이트의 **본문 문장/해석을 그대로 옮기지 않았다** — 구조·분류 방식만 참고하고, 최종
  설명은 전부 독자적으로 작성했다(지시문 §4/§45).

Parent와 의미가 겹치는 후보는 이번 Wave에서 의도적으로 제외했다(예: "물꿈"을 별도 Parent로

기존 Parent의 situation으로 흡수하는 쪽을 택했다.

## 3. P1 / P2 / P3 우선순위

- **P1** — 검색 의도가 명확하고 세부 상황이 다양해 10개 안팎의 situation을 채울 근거가 있는 꿈.
- **P2** — 검색 의도는 명확하지만 세부 상황이 P1만큼 다양하지 않은 꿈(5~8개).
- **P3** — 검색량은 있으나 이번 Wave에서 신규 Parent를 만들 만큼 우선순위가 높지 않아 다음
  Wave 후보로 남긴 꿈.

## 4. 기존 25 Parent Gap Analysis

기존 25개 Parent를 실제로 조회(`supabase/migrations/0010_seed_data.sql`, `0019_dream_situations_seed.sql`)한
결과, 카테고리 분포는 동물 10 / 신체 3 / 인물 2 / 상황 4 / 자연 4 / 행동 1 / 사물 2였다.

가장 뚜렷한 공백:
1. **교통 카테고리가 전무하다** — "자동차 꿈", "비행기 꿈"처럼 실제 검색량이 있는 계열이 하나도
   없었다.
2. **인물 카테고리가 조상/죽은 사람 2개뿐이다** — "아기꿈", "귀신꿈"처럼 검색 의도가 뚜렷한
   인물 계열이 비어 있었다.
3. **동물 카테고리 안에서도 고양이가 없다** — 개꿈은 있지만 고양이꿈이 없어, 반려동물 검색
   수요의 절반만 커버하고 있었다.
4. **신체 카테고리의 세부 상황이 얕다** — 이빨 빠지는 꿈(4개)은 "윗니/아랫니/피/개수" 같은
   실제 검색자가 궁금해하는 조건 분기를 아직 다 담지 못한 상태였다.
5. **자연 카테고리에 날씨 계열이 없다** — 불/물/산/바다는 있지만 비/눈/번개 같은 날씨 꿈이
   없었다.

## 7. 콘텐츠 깊이 기준

`0019_dream_situations_seed.sql`의 돼지꿈 12개를 그대로 품질 benchmark로 삼는다(지시문 §38) —
문단 하나(5~7문장)로 상황을 구체적으로 설명하고, "전통적으로 ~로 해석되곤 한다" 류의 완곡한
표현만 쓰며, 매 situation마다 실제로 다른 문장 구조/어휘를 쓴다. 신규/확장 situation도 동일
기준(§9~§10, §43)을 따른다 — 필요 없는 섹션(긍정적/조심할 부분 등)은 억지로 채우지 않는다.

## 8. Parent Hub 콘텐츠 모델 (지시문 §12 검토 결과)

새 column/table을 추가하지 않았다. 기존 `dreams.interpretation`(TEXT)에 `## 소제목` 줄을
포함시키는 경량 마크다운 규칙을 도입하고, `app/dream/[keyword]/page.tsx`가 이를 파싱해 실제
`<h2>`로 렌더링하도록 확장했다(기존 25개처럼 `##`가 없는 일반 텍스트는 지금과 동일하게 한
문단으로 렌더링 — 하위 호환). 상세 구현은 `docs/DREAM_SEO_EXPANSION_REPORT.md` §11 참조.

## 9. 다음 Wave 예고

P3 24개(§3)를 다음 확장 Wave의 1차 후보로 남긴다. 이번 Wave에서 만든 검색/관련꿈 인프라(§10~§20
of the report)는 다음 Wave 콘텐츠가 추가될 때도 그대로 재사용 가능하도록 설계했다.
