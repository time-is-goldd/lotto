# ADMIN REQUIREMENTS — 관리자 페이지 요구사항 (1인 운영 개정판)

> v2.0. [[MASTER_PRD]] §3 "1인 개발자 원칙"(운영 자동화 최우선, AI 위임 우선, 관리 화면 최소화)을 정면 반영해 전면 개정했다. [[CRITICAL_REVIEW]] A-01~A-05(역할체계 과설계, 반복작업 자동화 여지)를 해결한다.

---

## 0. 개정 원칙

1. **역할은 단일화한다.** v1.0의 `super`/`content_editor`/`community_manager` 3역할 체계를 **`admin` 단일 역할**로 통합한다. 팀원이 실제로 합류하는 시점에 역할 분리를 재도입한다 ([[MASTER_PRD]] 원칙 3).
2. **반복작업은 기본적으로 자동화 대상이다.** 아래 각 섹션에서 "수동(MVP) → 자동화(이후 Phase)" 전환 경로를 명시한다.
3. **AI 초안 → 사람 승인** 패턴을 콘텐츠 작업 전반에 기본값으로 적용한다.

---

## 1. 관리자 대시보드 (`/admin`)

핵심 지표 요약(오늘 신규가입, 오늘 번호생성, 다음 추첨까지 남은 시간, 미처리 신고 건수)은 유지. [[MASTER_PRD]] North Star Metric(다이어리 중심 멀티기능 사용률) 요약 위젯 추가.

## 2. 콘텐츠 관리 (`/admin/content`)

### 2.1 꿈해몽 관리
- CRUD 기능 유지 ([[FEATURE_SPEC]] §2)
- **자동화 경로**: MVP는 수동 작성(20~30건). Phase 8에서 "AI 초안 생성(키워드 입력 → 해몽 본문/추천번호풀 자동 생성) → 관리자가 검토 후 발행" 워크플로 도입. 미등록 검색어 리포트 기능은 유지(콘텐츠 갭 발견).

### 2.2 FAQ / 가이드 / 공지 관리 — 유지 (변경 없음)

## 3. 당첨/통계 관리 (`/admin/lottery`)

### 3.1 회차 결과 입력
- **MVP**: 수동 입력 폼 유지(회차/당첨번호6개/보너스번호/1등금액·인원).
- **자동화 경로(Phase 8)**: 공공데이터포털 로또 API로 자동 수집 → 관리자는 "확인" 버튼 1번 클릭으로 승인하는 더블체크 방식으로 전환. 완전 자동입력이 아닌 승인 단계를 남겨 오류 리스크를 관리한다.
- 입력/승인 즉시 당첨 자동확인 배치 실행 버튼 노출 ([[FEATURE_SPEC]] §1.3).

### 3.2 당첨 사례 관리
- **MVP**: 수동 작성(최소 큐레이션).
- **자동화 경로(Phase 8)**: 회차/등수/지역 데이터를 조합한 "AI 초안 문구 자동 생성 → 관리자 검토·발행" 워크플로.

### 3.3 로또 명당(판매점) 데이터 관리 (신규, Phase 4~)
- 공공데이터(1등 배출점 명단) 임포트 기능, 지역/좌표 정비, `store_win_records` 등록.

### 3.4 통계 확인 — 유지

## 4. 커뮤니티/배틀/성장 운영 (`/admin/engagement`, Phase 4~)

### 4.1 배틀 관리
- **MVP 범위 아님** (Phase 4).
- **자동화 경로(Phase 8)**: "직전 주 배틀 설정을 복제해 다음 회차로 자동 생성 → 관리자는 보상 문구만 확인/수정 후 발행"으로 매주 반복 생성 부담 제거.
- 보상 문구 저장 시 현금/상품권 관련 금지어(예: "현금", "상품권", "계좌이체") 포함 여부를 자동 검사해 저장을 차단하는 검증 로직 추가 ([[MASTER_PRD]] 비목표, [[FEATURE_SPEC]] §5.2).

### 4.2 명예의 전당 관리 — 유지 (Phase 4)

### 4.3 게시판 관리 (Phase 4)
- 신고 큐(`reports` 테이블, [[DATABASE_SCHEMA]] §3.15) 우선 처리 뷰
- **자동화**: 신고 5건 누적 시 자동 임시비공개 처리(완전삭제 아님) + 금지어 필터 사전 차단은 이미 발행 단계에서 적용

### 4.4 친구초대 현황 관리 (신규, Phase 4)
- 레퍼럴 발급/전환 현황 조회, 비현금 보상 지급 상태 확인

## 5. 회원 관리 (`/admin/users`) — 유지 (역할 언급만 단일화)

## 6. 알림 관리 (`/admin/notifications`)

- MVP: 사이트 내 알림 + 이메일/웹푸시 발송 이력 확인
- Phase 2 이후: 카카오 알림톡 템플릿 관리 화면 추가 (사업자등록 이후, [[FEATURE_SPEC]] §10)

## 7. 쇼핑몰/멤버십/파트너 관리 (Phase 5~7, MVP 범위 아님)

- Phase 1에서는 화면 자체를 만들지 않는다 (v1.0에서는 "사전알림 신청자 목록" 최소화면을 Phase1에 뒀으나, 이마저도 MVP 범위 밖으로 재조정 — [[ROADMAP]] Won't 항목).

## 8. 시스템/설정 관리 (`/admin/settings`)

- 사행성 금지어 리스트 관리 (게시글·배틀보상 문구 검증에 공통 사용)
- 감사로그 조회 (`admin_audit_logs`) — 개인정보 필드 마스킹 표시 ([[DATABASE_SCHEMA]] §3.23)
- 관리자 계정은 MVP에서 1개(본인 계정)만 존재 — 별도 계정관리 화면 불필요, Supabase Auth의 관리자 플래그로 충분

## 9. 관리자 UX 원칙 — 유지

파괴적 액션 2단계 확인, 목록 화면 검색/필터 기본 제공, 대량작업 dry-run 원칙은 유지.
